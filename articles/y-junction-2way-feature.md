# Y字路マップで2本の道路で構成されるY字路に対応しました

[前回](https://note.com/cozy_corner4321/n/n27f4311efe6d)、[前々回](https://note.com/cozy_corner4321/n/n284a2a2c5711)に続いて、Y字路マップを更新したので紹介します。

渋谷のキャットストリートには、[日経新聞でも紹介された](https://www.nikkei.com/article/DGXMZO81606990W5A100C1TBQ000/)Y字路があります。Google Street Viewで見ても3方向に道路が分かれている典型的なY字路ですが、これまでY字路マップには表示されていませんでした。

<!-- 画像: 渋谷のY字路のGoogle Street View -->

調べてみると、OpenStreetMap（OSM）上では、このY字路は2本の道路で表現されていました。

サービスはこちら: https://storage.googleapis.com/y-junctions-prod-frontend/index.html

## 2本の道路で表現されるY字路

OSM上では、このY字路はキャットストリートと脇道の2本の道路で表現されていました。

これまでY字路マップでは、3本の道路が接続している場所をY字路として検出していました。そのため、2本の道路で表現されているこのY字路は検出されていませんでした。

OSMでは、視覚的にはY字路であっても、2本の道路として表現されることがあります。

### なぜ2本の道路で表現されるのか

OSMでは、道路は複数の地点（ノード）をつないだ線として記録されています。メイン道路が1本の道路（Way）として連続し、途中のノードで脇道が接続する場合、そのノードには2本の道路しか接続していません。

```
例：渋谷のY字路のデータ構造
Way 520422791（キャットストリート）:
  [..., ノードA, ノード1522928021, ノードB, ...]
                        ↓
                   このノードがY字路

Way 138913755（脇道）:
  [..., ノードC, ノード1522928021]
                        ↓
                  ここで接続
```

<!-- 図: データ構造の視覚化 -->

しかし、幾何学的に見れば、このノードには**3方向**の道路が接続しています。

```
     キャットストリート（進入方向）
       ノードA → ノード1522928021
              ↗ (方位角 74.9°)
             /
   脇道    /
   ノードC /
  (39.6°) /
        ↗ /
         /
        ● ノード1522928021
         \
          \
           ↘ キャットストリート（退出方向）
             ノード1522928021 → ノードB
                (方位角 236.8°)
```

<!-- 図: 3方向のベクトルと方位角の視覚化 -->

### 角度の計算

[第1回の記事](https://note.com/cozy_corner4321/n/n91147a760c68)で説明した方法と同じように、このノードから各方向への方位角（北を0度として時計回りに測った角度）を計算します。

- **進入方向**（ノードA → ノード1522928021）: 74.9°
- **退出方向**（ノード1522928021 → ノードB）: 236.8°
- **接続方向**（ノードC → ノード1522928021）: 39.6°

これらをソートして、隣り合う方向間の角度を計算すると：

```
ソート後: [39.6°, 74.9°, 236.8°]

角度1 = 74.9° - 39.6° = 35.3°
角度2 = 236.8° - 74.9° = 161.9°
角度3 = 360° - 236.8° + 39.6° = 162.8°

合計: 35.3° + 161.9° + 162.8° = 360° ✓
```

<!-- 図: 角度計算の視覚化（第1記事と同じスタイル） -->

最小角度は**35.3度**です。これはY字路の定義（最小角度が10度以上60度未満）を満たしており、「鋭角」タイプ（30° ≤ 最小角度 < 45°）に分類されます。

## 2本の道路で構成されるY字路の検出方法

この問題を解決するため、新しい検出ロジックを追加しました。

### 基本的な考え方

接続している道路が2本の場合でも、以下の条件を満たせば、幾何学的には3方向の分岐があると判定できます：

- 少なくとも1本の道路が、そのノードを**通過**している（始点・終点ではない）
- その道路の「進入方向」と「退出方向」、そして接続する道路の方向で、合計3方向

### 検出条件

以下の条件を満たすノードを「2本の道路で構成されるY字路」として検出します：

#### 1. 構造的条件

- 接続している道路がちょうど2本
- 少なくとも1本の道路が、そのノードを通過している（始点・終点ではない）
- 両方の道路が対象となる道路種別（主要道路、生活道路、歩行者道路など）

#### 2. 幾何学的条件

3方向の方位角を計算します：

1. **通過する道路の進入方向**：前のノード → 当該ノード
2. **通過する道路の退出方向**：当該ノード → 次のノード
3. **接続する道路の方向**：隣接ノード → 当該ノード（または逆）

これらの方位角から、3方向間の角度を計算し、最小角度が**60度未満**であれば、Y字路として検出します（T字路との境界）。

### 除外されるケース

以下のようなケースは除外されます：

#### 両方の道路が終点の場合
```
Way A ────> [ノード] <──── Way B
```
通過する道路が存在しないため、2本の道路の単純な接続点とみなし、除外されます。

#### 最小角度が60度以上の場合
```
Way A ──────> [ノード] ──────> (ほぼ直進)
              ↑
           Way B (接続)
```
最小角度が60度以上になる場合、T字路とみなして除外されます。

この方法により、OSM上の構造に関わらず、「実際に3方向に分岐しているY字路」を検出できるようになりました。

## データの大幅増加

今回の対応を全国データに適用した結果、Y字路の総数が大幅に増加しました：

- **従来**: 256,305箇所
- **対応後**: 679,065箇所
- **増加数**: +422,760箇所（**+165%増加**）

渋谷のキャットストリート付近のY字路も検出対象に含まれています。

## どんなY字路が新しく検出されるようになったか

今回の対応で検出可能になったY字路の例：

1. **都市部の複雑な交差点**
   - メイン道路が緩やかにカーブしながら、脇道が接続するパターン
   - 渋谷のような繁華街に多い

<!-- 画像: 都市部のY字路の例 -->

2. **歩行者道路の分岐**
   - 階段（steps）、歩行者専用道路（pedestrian）、小道（path）の組み合わせ
   - 公園や住宅街に多い

<!-- 画像: 歩行者道路のY字路の例 -->

3. **生活道路とservice道路の接続**
   - 幹線道路にservice道路やalleyが接続
   - 視覚的には明確な分岐点

<!-- 画像: 生活道路のY字路の例 -->

## 今後について

今回の対応により、2本の道路で表現されているY字路も検出できるようになりました。

引き続き、次のような更新を進めていきます。

- 書籍などで紹介されている有名なY字路の検出精度向上
- 明らかにY字路でない箇所が表示される原因の調査と除外

海外などの地域を広げるアップデートは、その後を予定しています。
